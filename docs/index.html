01 · THE AGENTS

    
Five agents, three models. The strongest model only where a decision is made.

    
Each agent has one job, a fixed JSON answer format and only the context it needs. Cheap models do the writing; their answers are checked by code and redone one model up when the check fails. Code, not a model, decides whether anything ships.

    

      
    

    

      
Analyst
Haiku → Sonnet
Turns the issue into testable requirements. Checked by code; an empty answer is redone on Sonnet.

      
Architect
Opus · decides
Approves or rejects the scope from a map of the code, and names the only files that may change.

      
Developer
Sonnet → Opus
Writes small edits and table-driven tests until gofmt, vet, race tests and lint pass. Opus only after a failed gate.

      
QA
Opus · decides
Gives the merge verdict from the diff, judged against the issue and the approved plan.

      
Docs
Haiku → Sonnet
Writes the PR description and changelog with the real field names, checked by code like the analyst.

03 · TOKEN ENGINEERING

    
Spend the strong model on decisions. Send each agent only what it needs.

    

      
route()
Model routing
Opus for scope and merge decisions, Sonnet for code, Haiku for requirements and docs. Escalation happens only on evidence: a failed check or a failed gate.

      
repomap
Context packing
A map of declarations is 1,116 characters instead of 6,295 for the source, 82% smaller. Only the developer sees full files, and only the ones the architect picked. QA sees the diff.

      
json_schema
Structured output
Every agent answers in a strict JSON schema: no prose to pay for, nothing to parse. Validators catch what a schema cannot, such as a valid but empty answer.

      
edits[]
Edits, not files
The developer sends find-and-replace edits that must match exactly once. On issue #1, run output fell from 13,320 tokens to 8,565.

      
tail(40)
Compact feedback
A failed gate sends back only the failing check and its last 40 lines. The retry continues the same conversation, so its start is read from cache.

      
cache_control
Caching, measured
A probe showed the output schema is part of the cached prefix, so agents never share a cache. Breakpoints sit only where a prompt is re-sent. At this size it saved little: 3.6% of prompt tokens.

05 · VS. BY HAND

    
On small, generic issues the agents were faster and cheaper. Here is exactly how that is counted.

    

      

        
Agents, then a person reviews

        
~7 min · ~$5.62

        
    
          
  • Agent work: ~2 min per issue, model cost $0.17 measured
    • 
          
  • CI: ~4 min per PR, unattended measured
    • 
          
  • Human review before merge: ~5 min, $5.45 estimate
    • 
        

      

      

        
A software engineer by hand

        
~1 h · ~$65.38

        
    
          
  • Read the issue, write the change and ~100 lines of tests, run the checks, write the PR: ~1 hour assumption
    • 
          
  • Pay: $65.38 an hour, the median for U.S. software developers (BLS, May 2025: $135,980 a year), wage only official data
    • 
        

      

    

    

      
Where this worked
  • Small, well-scoped issues with a clear expected behaviour
  • A codebase with good tests and fast CI, so the gates can judge the code
  • Changes that stay inside a few files the architect can name

      
Where it is not shown to work
  • Large codebases, cross-service changes, real design trade-offs
  • Vague issues: the analyst invented scope once, and QA enforced it
  • Code without tests: the gates are what make the agents safe

    

    
Three issues is a small sample, and the hand-coding time was not timed. Even at 15 minutes by hand ($16) the agent path costs less, and at 5 minutes of review it is the person's time, not the model, that makes up most of the agent-side cost. Source: BLS Occupational Outlook Handbook, Software Developers. Total spent on every run on this page, failures and experiments included: $2.13.

  






  

    
06 · WHAT BROKE

    
Twelve failures, each with the change it caused.

    

      
Cheap models return empty answers
Haiku twice returned schema-valid but empty output: requirements reading "placeholder", and a PR with no title or changelog. The release gate blocked that PR. Every cheap step now has a validator and one retry a model up.

      
CI checked more than the harness
An agent PR passed the local gates and QA, then failed CI lint. The same linter now runs inside the developer's loop.

      
I broke main
I committed an unformatted file the developer may not touch, and three attempts failed for $0.19. The harness now runs the gates on the base before any model call.

      
A revision destroyed a green version
QA asked for work the issue never mentioned; the revision broke the tests and nothing rolled back. Now the last green version is kept, and QA judges against the issue and the plan.

08 · RUN IT

    
One Go binary.

    
# .env holds ANTHROPIC_API_KEY
go build -o sdlc ./cmd/sdlc
./sdlc map                       # the repo map the agents see
./sdlc run -issue 1 -pr          # issue → requirements → plan → edits ⇄ gates → QA → docs → PR
./sdlc run -issue 1 -route opus  # routing comparison: every agent on Opus
./sdlc naive -issue 1            # baseline: one Opus call with the whole repo
./sdlc redoc -issue 1            # redo only the docs step on an open PR
go run ./cmd/analyst-eval        # which model should write requirements
go run ./cmd/metrics             # ledger + GitHub → results/metrics.json
